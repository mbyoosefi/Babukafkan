# Babukafkan v3.0.0

## Evidence-based ESXi recovery with journal-first transactions

<div dir="rtl" align="right">

این نسخه، تجربهٔ بازیابی عملیاتی پروژه را به یک هستهٔ جداگانه با شواهد صریح، برنامهٔ دقیق تعمیر، پشتیبان اختصاصی و سابقهٔ پایدار پیش از نوشتن ارتقا می‌دهد. نسخهٔ تاریخی برای مقایسه و آزمون محفوظ مانده است.

### تغییر اصلی

هیچ تغییر منبعی بدون بررسی شواهد و ثبات منبع، پشتیبانِ بازخوانی‌شده و ثبت پایدار پیش از نوشتن انجام نمی‌شود. بایت‌های نوشته‌شده دوباره خوانده می‌شوند؛ نتیجهٔ ساختاری و معنایی، در صورت وجود بررسی‌کننده، جدا ثبت می‌شود. بازگشت از شناسهٔ تراکنش و حالت مورد انتظار انجام می‌شود.

### امکانات

- تحلیل دسته‌ای و پیش‌نمایش بدون تغییر منبع؛ تعمیر و بازگشت با مجوز صریح.
- ادامهٔ اسکن با اثرانگشت معتبر، گزارش پیشرفت و حفظ نامزدهای ردشده.
- خواندن واقعی چند رکورد فایل‌سیستم و بررسی سخت‌گیرانه‌تر ساختارها و نسخهٔ آینه.
- بازسازی جدول پارتیشن از شواهد معتبر، بدون اختراع وضعیت فعال بر اساس اندازه.
- ساخت توصیفگر فقط برای دیسک پایهٔ تختِ شناخته‌شده؛ توقف روی زنجیره‌های پراکنده و ناشناخته.
- گزارش انسانی و ماشینی، ثبت شکست‌ها و جلوگیری از تکرار همان اقدام شکست‌خورده بدون تغییر مرتبط.
- راهنمای کامل فارسی و انگلیسی برای ورودی جدید و تمام ابزارهای مکمل و تاریخی.

### نتیجهٔ اعتبارسنجی

۷۵ آزمون مصنوعی موفق هستند. آزمون تطبیقی، منطق نسخهٔ تاریخی را روی دیسکی فراتر از مرز تخریب بررسی می‌کند و زنجیرهٔ تعمیر را سپس به ترتیب معکوس بازمی‌گرداند. آزمون‌های قطع اجرا، خرابی پشتیبان، شکست سابقه، اختلاف بازخوانی، شکست ساختاری و معنایی، منبع در حال استفاده و اجرای دوباره نیز پوشش داده شده‌اند.

این انتشار در محیط میزبان واقعی اعتبارسنجی عملیاتی نشده است. پشتیبانی از تغییر نام با پیوند سخت، تضمین همگام‌سازی ذخیره‌ساز و تأیید بومی زنجیره باید در مقصد بررسی شوند. تعریف جریان کار خودکار، ادعای موفقیت اجراهای انجام‌نشده نیست. تأیید ساختار دیسک، تضمین محتوای همهٔ فایل‌ها یا راه‌اندازی مهمان نیست.

### مهاجرت

پوشهٔ نسخهٔ جدید را کامل و جدا از مرجع تاریخی مستقر کنید. فضای وضعیت را پایدار تعیین کنید و ابتدا تحلیل یا پیش‌نمایش بگیرید. گزینه‌ها و پشتیبان‌های تاریخی خودکار به مدل جدید تبدیل نمی‌شوند. ابزارهای مکملِ قدیمی که امکان نوشتن دارند، زیر پوشش موتور تراکنش جدید نیستند.

## English

Version 3.0.0 preserves the original recovery reference and introduces a separate standard-library transaction core. Mutation requires unique verified evidence, stable source state, an independently verified exclusive backup and a durable journal before writing. Every write receives exact readback; structural and available semantic checks are recorded separately. Rollback consumes recorded transaction IDs and rejects unexpected source states.

### Included

- Deterministic analysis/planning, interactive or explicitly authorized batch repairs, transaction-ID rollback and journal inspection.
- Source fingerprints/full-hash option, resumable scan checkpoints, scoped negative evidence and rejected alternatives.
- NTFS record/USA/attribute checks, usable MFTMirr consistency, GPT CRC/reciprocity/bounds and MBR geometry/overlap validation.
- No largest-partition active heuristic, no sparse/snapshot guessing and no deletion of encrypted descriptor evidence.
- JSON/text reports, forensic transaction artifacts and explicit failure/result states.
- Complete Persian/English manuals, file inventory, historical-tool boundaries and synthetic CI.

### Validation

75 synthetic tests passed locally. Live ESXi/VMFS validation is not claimed. Python 3.5 syntax compatibility is checked; self-tests need Python 3.8+. Safe rename hardlinks, storage durability and independent native VMware chain validation require deployment-specific checks. No whole-payload or guest-boot guarantee is implied.
